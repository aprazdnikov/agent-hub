# agent-hub

**Каждая тема Telegram-группы — отдельная сессия AI-агента на вашей машине.**

Создали тему «Починить тесты в backend» — получили новую сессию Claude Code. Пишете в тему
задачу, агент работает в вашей рабочей директории, присылает ответы и спрашивает кнопками
разрешение на команды и правки. Темы живут параллельно и независимо, контекст каждой
сохраняется между сообщениями и перезапусками бота.

Сейчас поддерживается один бэкенд — **Claude** (через
[Claude Agent SDK](https://platform.claude.com/docs/en/agent-sdk/overview)). Архитектура
рассчитана на добавление других агентов — см. [Добавление бэкенда](#добавление-бэкенда).

```
Telegram (форум-группа)
  ├─ тема «backend: тесты»   → сессия Claude, cwd ~/Projects/shop/backend
  ├─ тема «agent-hub»        → сессия Claude, cwd ~/Projects/aprazdnikov/agent-hub
  └─ тема «идеи»             → сессия Claude, cwd ~/Projects
```

> ⚠️ Бот исполняет команды на вашей машине от вашего пользователя. Прочитайте
> [Безопасность](#безопасность) до запуска.

## Требования

| Что | Зачем |
|---|---|
| Linux или macOS | Там, где будет работать агент |
| [uv](https://docs.astral.sh/uv/) **или** Docker с Compose | Запуск на хосте (Python 3.12+ uv поставит сам) или [в контейнере](#запуск-в-docker) |
| [Claude Code](https://code.claude.com/docs/en/setup), выполненный вход (`claude` → `/login`) или `ANTHROPIC_API_KEY` | SDK запускает Claude Code и берёт его авторизацию |
| Telegram-аккаунт | Создать бота и группу |

## Быстрый старт

### 1. Создайте бота

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и username.
2. Сохраните токен вида `123456789:AA...`.
3. Там же выполните `/setcommands`, выберите бота и вставьте список, чтобы команды
   подсказывались в Telegram:

   ```
   new - Новая сессия: /new [backend] [путь]
   cwd - Сменить рабочую директорию
   reset - Сбросить контекст разговора
   stop - Прервать текущую задачу
   status - Состояние сессии
   help - Справка
   ```

### 2. Создайте форум-группу

1. Создайте группу в Telegram.
2. **Настройки группы → Темы (Topics) → включить.** Группа станет форумом.
3. Добавьте бота в группу и **сделайте его администратором** — так он видит все сообщения и
   события создания тем. Права: достаточно «Управление темами»; остальные можно снять.

### 3. Установите проект

```bash
git clone git@github.com:aprazdnikov/agent-hub.git
cd agent-hub
uv sync
cp .env.example .env
chmod 600 .env
```

Заполните в `.env` токен, `AGENT_HUB_WORKSPACE_ROOT` и временно поставьте
`AGENT_HUB_CHAT_ID=0`, `AGENT_HUB_ALLOWED_USER_IDS=0` — реальные ID узнаем на следующем шаге.

### 4. Узнайте ID группы и свой user id

```bash
uv run --env-file .env agent-hub
```

Напишите любое сообщение в группу. Бот его отклонит и запишет в лог оба ID:

```
... WARNING agent_hub.bot: rejected update chat_id=-1001234567890 user_id=123456789
```

Остановите бота (`Ctrl+C`) и впишите значения в `.env`:

```dotenv
AGENT_HUB_CHAT_ID=-1001234567890
AGENT_HUB_ALLOWED_USER_IDS=123456789
```

### 5. Запустите

```bash
uv run --env-file .env agent-hub
```

Создайте в группе тему — бот ответит «🆕 Новая сессия» с рабочей директорией. Напишите в теме
задачу, например: `Посмотри структуру проекта и кратко опиши его`.

## Использование

### Темы и сессии

- **Новая тема = новая сессия** в `AGENT_HUB_WORKSPACE_ROOT`. Если бот был выключен, когда
  создавали тему, сессия создастся при первом сообщении.
- **Обычное сообщение в теме** — очередная реплика в сессии. Контекст сохраняется.
- **Общая тема (General)** не используется — бот попросит создать отдельную тему.
- В одной теме одновременно выполняется одна задача; разные темы работают параллельно.

### Команды

| Команда | Что делает |
|---|---|
| `/new [backend] [путь]` | Новая сессия в этой теме: сброс контекста, опционально бэкенд и директория |
| `/cwd <путь>` | Сменить рабочую директорию (контекст сбрасывается) |
| `/reset` | Начать разговор заново в той же директории |
| `/stop` | Прервать выполняющуюся задачу |
| `/status` | Бэкенд, директория, ID сессии, занята ли тема |
| `/help` | Справка |

Пути — абсолютные, с `~` или относительные от `AGENT_HUB_WORKSPACE_ROOT`. Выйти за пределы
корня нельзя, в том числе через симлинки.

```
/new shop/backend
/new claude ~/Projects/aprazdnikov/agent-hub
/cwd shop/frontend
```

### Подтверждение действий

Когда агенту нужно выполнить команду или изменить файл, а это не разрешено заранее, в тему
приходит сообщение:

```
🔐 Bash
uv run pytest tests/test_orders.py
[✅ Разрешить] [❌ Запретить]
```

Без ответа за `AGENT_HUB_APPROVAL_TIMEOUT_SECONDS` (по умолчанию 10 минут) вызов запрещается,
агент получает отказ и продолжает работу с его учётом.

Что спрашивается, а что нет, решают:

1. `AGENT_HUB_CLAUDE_PERMISSION_MODE` — см. [Конфигурация](#конфигурация).
2. Ваши настройки Claude Code: бот загружает `~/.claude/settings.json`,
   `.claude/settings.json` и `.claude/settings.local.json` проекта. Всё, что вы разрешили в
   `permissions.allow`, выполняется без вопросов — так же, как в терминале. Там же
   подхватываются `CLAUDE.md`, скиллы, MCP-серверы и хуки.

### Что приходит в тему

- текст ответов агента с форматированием: Markdown агента переводится в разметку Telegram —
  жирный, курсив, `код`, блоки кода с подсветкой языка, ссылки, цитаты; заголовки становятся
  жирным текстом, списки — строками с маркерами, таблицы — моноширинным блоком. Длинные
  ответы делятся на несколько сообщений по границам блоков. Если Telegram не примет разметку,
  сообщение уйдёт обычным текстом;
- `🔧 Tool: …` — каждый вызов инструмента одной строкой;
- `✅ Готово · ходов: N · $0.42` — задача завершена;
- `❌ …` — ошибка агента, `⏹ Остановлено` — после `/stop`.

## Конфигурация

Все настройки — переменные окружения (файл `.env` или `EnvironmentFile` в systemd).

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `AGENT_HUB_TELEGRAM_TOKEN` | да | — | Токен бота |
| `AGENT_HUB_CHAT_ID` | да | — | ID форум-группы; сообщения из других чатов игнорируются |
| `AGENT_HUB_ALLOWED_USER_IDS` | да | — | Кому разрешено управлять, через запятую |
| `AGENT_HUB_WORKSPACE_ROOT` | да | — | Корень рабочих директорий и директория по умолчанию |
| `AGENT_HUB_STATE_FILE` | нет | `~/.local/state/agent-hub/topics.json` | Привязка тем к сессиям |
| `AGENT_HUB_APPROVAL_TIMEOUT_SECONDS` | нет | `600` | Ожидание ответа на запрос разрешения |
| `AGENT_HUB_CLAUDE_PERMISSION_MODE` | нет | `default` | Режим разрешений Claude Code, см. ниже |
| `AGENT_HUB_CLAUDE_MODEL` | нет | из настроек Claude Code | Модель, например `claude-opus-5-5` |
| `AGENT_HUB_CLAUDE_MAX_BUDGET_USD` | нет | без лимита | Лимит стоимости одной задачи (одного сообщения) |

Режимы разрешений:

| Режим | Поведение |
|---|---|
| `default` | Спрашивает всё, что не разрешено в ваших настройках. **Рекомендуется** |
| `acceptEdits` | Правки файлов без вопросов, команды — с подтверждением |
| `plan` | Только чтение и план, без изменений |
| `bypassPermissions` | Без подтверждений вообще. Только в изолированном окружении |

## Запуск в Docker

Директория хоста монтируется в контейнер как `/workspace` — это и есть корень рабочих
директорий для всех тем. Есть два варианта образа, выбираются `AGENT_HUB_IMAGE` в `.env`:

| Вариант | Что внутри | Для чего |
|---|---|---|
| `base` (по умолчанию) | Python 3.12, git, ssh, curl, Claude Code | Python, скрипты, документация |
| `dev` | `base` + JDK 25, Maven 3.9, Node.js 24, npm, Docker CLI | Java/Maven и JavaScript-проекты |

Claude Code поставляется вместе с SDK, отдельный Node.js для него не нужен. Версии
инструментов `dev` меняются аргументами сборки `JAVA_VERSION`, `MAVEN_VERSION`,
`NODE_VERSION`, `DOCKER_VERSION` в [`Dockerfile`](Dockerfile).

### 1. Настройте `.env`

Заполните обязательные переменные из [Конфигурации](#конфигурация) и добавьте:

```dotenv
# что смонтировать как /workspace
AGENT_HUB_HOST_WORKSPACE=/home/you/Projects
# ваш `id -u` и `id -g` — чтобы файлы в /workspace принадлежали вам
AGENT_HUB_UID=1000
AGENT_HUB_GID=1000
# для Java/Node-проектов
AGENT_HUB_IMAGE=dev
# переиспользовать локальный Maven-репозиторий хоста (иначе — отдельный том m2)
AGENT_HUB_HOST_M2=/home/you/.m2
```

`AGENT_HUB_WORKSPACE_ROOT` и `AGENT_HUB_STATE_FILE` в контейнере переопределяются на
`/workspace` и `/data/topics.json`, поэтому один `.env` подходит и для хоста, и для Docker.
Пути в командах бота считаются от `/workspace`: при `AGENT_HUB_HOST_WORKSPACE=/home/you/Projects`
команда `/cwd shop/backend` откроет `/home/you/Projects/shop/backend`.

### 2. Соберите образ

```bash
docker compose build
```

### 3. Авторизуйте Claude

Один из вариантов:

- **Вход по подписке внутри контейнера** — выполняется один раз, данные сохраняются в томе
  `claude`:

  ```bash
  docker compose run --rm -it --entrypoint claude agent-hub
  # в Claude Code: /login, после входа — /exit
  ```

- **API-ключ:** `ANTHROPIC_API_KEY=sk-ant-...` в `.env`.
- **Долгоживущий токен подписки:** выполните `claude setup-token` на хосте и положите результат
  в `CLAUDE_CODE_OAUTH_TOKEN` в `.env`.

### 4. Запустите

```bash
docker compose up -d
docker compose logs -f
```

ID группы и пользователя узнаются так же, как в [шаге 4](#4-узнайте-id-группы-и-свой-user-id)
быстрого старта — строки `rejected update` будут в `docker compose logs`.

Управление:

```bash
docker compose restart          # после правки .env
docker compose down             # остановить; тома с состоянием и логином сохраняются
docker compose build && docker compose up -d   # после обновления кода
```

### Что где хранится

| Путь в контейнере | Откуда | Содержимое |
|---|---|---|
| `/workspace` | `AGENT_HUB_HOST_WORKSPACE` (bind mount) | Ваши проекты, с ними работает агент |
| `/data` | том `data` | `topics.json` — привязка тем к сессиям |
| `/home/app/.claude` | том `claude` | Логин, настройки и история сессий Claude Code |
| `/home/app/.m2` | `AGENT_HUB_HOST_M2` или том `m2` | Локальный Maven-репозиторий |
| `/home/app/.npm` | `AGENT_HUB_HOST_NPM` или том `npm` | Кеш npm |

Монтирование `~/.m2` хоста полезно, когда в нём есть артефакты, которых нет в публичных
репозиториях (собранные локально внутренние библиотеки), и чтобы не качать зависимости заново.

### Docker внутри агента (Testcontainers)

Интеграционные тесты на Testcontainers или `docker compose` требуют Docker. Файл
[`compose.docker.yaml`](compose.docker.yaml) даёт агенту доступ к Docker хоста: монтирует
сокет, добавляет группу `docker`, направляет Testcontainers на хост через
`host.docker.internal` и монтирует рабочую директорию **по тому же пути, что на хосте** —
демон разрешает пути bind-mount на хосте, поэтому `/workspace` для этого не подходит.

> ⚠️ Доступ к Docker-сокету равен правам root на хосте: агент может запустить контейнер,
> смонтировав в него любую директорию. Включайте, только если нужны такие тесты, и держите
> `AGENT_HUB_CLAUDE_PERMISSION_MODE=default`, чтобы каждая команда шла через подтверждение.

Включение — в `.env`:

```dotenv
AGENT_HUB_IMAGE=dev
AGENT_HUB_DOCKER_GID=999          # getent group docker | cut -d: -f3
COMPOSE_FILE=compose.yaml:compose.docker.yaml
```

`COMPOSE_FILE` подключает оба файла, поэтому команды остаются прежними —
`docker compose build`, `docker compose up -d`. Корень рабочих директорий в этом режиме
совпадает с путём на хосте, например `/home/you/Projects`, а не `/workspace`.

### Особенности

- **Другие инструменты.** Если не хватает того, что есть в `dev` (`go`, `gradle`, `psql` и
  т. п.), унаследуйте образ и доустановите:

  ```dockerfile
  FROM agent-hub:dev
  USER root
  RUN apt-get update && apt-get install -y --no-install-recommends postgresql-client \
      && rm -rf /var/lib/apt/lists/*
  USER app
  ```

- **Настройки Claude Code.** Контейнер не видит ваш `~/.claude` на хосте: у него свои
  `settings.json` и `CLAUDE.md` в томе `claude`. Проектные `.claude/settings.json` и `CLAUDE.md`
  внутри `/workspace` подхватываются как обычно. Монтировать весь `~/.claude` с хоста не
  стоит — хуки и плагины там часто ссылаются на пути хоста.
- **Git от вашего имени.** Чтобы агент мог коммитить и пушить, добавьте в `compose.yaml`
  в `volumes` (только чтение):

  ```yaml
      - ~/.gitconfig:/home/app/.gitconfig:ro
      - ~/.ssh:/home/app/.ssh:ro
  ```

- **Изоляция.** Контейнер видит только `/workspace`, а не весь домашний каталог. Это заметно
  безопаснее запуска на хосте, но внутри `/workspace` агент может всё, что разрешено его
  режимом.

## Запуск в фоне (systemd)

Юнит пользовательского systemd лежит в [`deploy/agent-hub.service`](deploy/agent-hub.service).
Он ожидает проект в `~/Projects/aprazdnikov/agent-hub` — поправьте `WorkingDirectory`, если
путь другой.

```bash
mkdir -p ~/.config/agent-hub ~/.config/systemd/user
cp .env ~/.config/agent-hub/env
chmod 600 ~/.config/agent-hub/env
cp deploy/agent-hub.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now agent-hub

# чтобы бот работал без открытой сессии пользователя
sudo loginctl enable-linger "$USER"
```

Логи и управление:

```bash
journalctl --user -u agent-hub -f
systemctl --user restart agent-hub
```

При остановке бот прерывает выполняющиеся задачи и пишет в их темы «⏹ Остановлено».
Привязки тем и ID сессий сохраняются, после перезапуска разговор продолжится.

## Безопасность

Бот даёт управление вашей машиной через Telegram. Защита:

- **Allowlist.** Обрабатываются только сообщения и нажатия кнопок от
  `AGENT_HUB_ALLOWED_USER_IDS` и только в группе `AGENT_HUB_CHAT_ID`. Всё остальное
  отбрасывается до любых обработчиков и логируется.
- **Подтверждения.** В режиме `default` каждое неразрешённое действие ждёт вашей кнопки.
- **Граница директорий.** `/new` и `/cwd` не выходят за `AGENT_HUB_WORKSPACE_ROOT`.
  Сам агент в режиме `bypassPermissions` этим не ограничен — это граница выбора
  директории, а не песочница.
- **Токен не попадает в логи**: логирование запросов `httpx` (URL содержит токен) приглушено.

Рекомендации:

- Храните `.env` с правами `600`, не коммитьте его (он в `.gitignore`).
- Не используйте `bypassPermissions` на рабочей машине. Если нужна полная автономия —
  запускайте бота [в Docker](#запуск-в-docker), смонтировав только нужные репозитории.
- При утечке токена: `@BotFather` → `/revoke`, затем обновите `.env`.
- Не добавляйте в группу посторонних: allowlist защищает от их команд, но они будут видеть
  переписку и вывод агента.
- Сообщения идут через серверы Telegram — не присылайте туда секреты и помните, что агент
  может процитировать содержимое файлов.

## Как это устроено

```
src/agent_hub/
├── __main__.py        # точка входа: конфиг, хранилище, бэкенды, запуск polling
├── config.py          # разбор переменных окружения в типизированные Settings
├── domain.py          # TopicKey, TopicSession, события агента, решения по разрешениям
├── bot.py             # Telegram: обработчики, запуск задач, кнопки подтверждения
├── approvals.py       # ожидающие подтверждения и формат callback_data кнопок
├── store.py           # JSON-файл «тема → сессия», атомарная запись
├── workspace.py       # проверка рабочих директорий
├── render.py          # разбиение длинных сообщений, форматирование
├── markdown_html.py   # Markdown агента → HTML-разметка Telegram
├── commands.py        # разбор аргументов команд
├── logs.py            # формат логов key=value
└── backends/
    ├── __init__.py    # протоколы AgentBackend и ApprovalGate
    └── claude.py      # адаптер Claude Agent SDK
```

Одно сообщение в теме — один «ход»:

1. `bot.py` находит сессию темы (или создаёт) и запускает ход в фоновой задаче, поэтому бот
   остаётся отзывчивым к кнопкам и другим темам.
2. Бэкенд возобновляет сессию по сохранённому `session_id` и отдаёт поток событий:
   `SessionStarted`, `AssistantText`, `ToolCall`, затем ровно одно `Finished` или `Failed`.
3. Запросы разрешений идут через `ApprovalGate` → сообщение с кнопками → ожидание ответа.
4. `session_id` сохраняется сразу при старте хода, поэтому даже после падения бота
   разговор можно продолжить.

### Добавление бэкенда

1. Добавьте значение в `BackendKind` (`domain.py`).
2. Реализуйте `AgentBackend` в `backends/<name>.py`: метод `run(session, prompt, gate)`
   возвращает асинхронный генератор событий и завершается `Finished` или `Failed`.
   Ошибки агента не пробрасываются исключениями — только событием `Failed`.
3. Добавьте ветку в `build_backend` (`__main__.py`). `mypy` через `assert_never` подскажет,
   если ветку забыли.

После этого бэкенд доступен как `/new <name> [путь]`.

## Разработка

```bash
uv sync                          # зависимости + dev-инструменты, фиксируются в uv.lock
uv run pre-commit install        # проверки перед каждым коммитом
```

Проверки — те же, что в CI ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)):

```bash
uv run ruff format --check .
uv run ruff check .
uv run mypy
uv run pytest --cov
```

Уровень строгости (настройки в [`pyproject.toml`](pyproject.toml)):

| Инструмент | Режим |
|---|---|
| mypy | `strict` + `warn_unreachable`, `extra_checks` и доп. коды: `exhaustive-match`, `possibly-undefined`, `redundant-expr`, `truthy-bool`, `unused-awaitable`, `explicit-override`, `ignore-without-code` и др. |
| ruff | все правила (`select = ["ALL"]`), отключены только конфликтующие с форматтером и docstring-правила; в тестах разрешён `assert` |
| pytest | `--strict-markers`, `--strict-config`, `xfail_strict`, любое предупреждение — ошибка |
| pre-commit | ruff format, ruff check, mypy, pytest на каждый коммит |

Закрытые варианты (события агента, решения, бэкенды, режимы) разбираются через `match` с
`assert_never`: добавили новый вариант и забыли обработать — mypy не пропустит.

Тесты покрывают конфиг, хранилище, проверку директорий, подтверждения, форматирование и
преобразование сообщений Claude SDK в события. Сквозной сценарий с Telegram и Claude
проверяется вручную в тестовой группе.

## Ограничения

- Только текст: фото, файлы и голосовые сообщения игнорируются.
- Интерактивные вопросы агента с вариантами ответа (`AskUserQuestion`) не поддерживаются
  отдельно и приходят как запрос разрешения на инструмент. Запретите его и ответьте текстом
  следующим сообщением.
- Ответ приходит целыми блоками после каждого шага агента, а не посимвольно.
- Одна форум-группа на экземпляр бота.
